# AGENTS.md

## Developer profile

- I am a **beginner in C#**, but not a complete one: I have some notions (basic syntax, variables, conditions, loops, simple classes).
- I do not yet master more advanced concepts (LINQ, async/await, generics, dependency injection, etc.).
- I communicate in **French**: all our conversations are **always in French** (explanations, plans, questions, validations, summaries).
- Only this `AGENTS.md` file must be written in English. Everything else you say to me is in French.

## How to work with me

### 1. Always go through plan mode

Before **any** implementation (creating or modifying code, files, or configuration), you must:

1. **Enter plan mode** and analyze the request.
2. **Present a plan in French**: what you intend to do, in which files, and in what order.
3. **Explain the logic** behind your choices (why this approach, what alternatives exist).
4. **Wait for my explicit validation** before writing or modifying anything.

Never move on to implementation without my approval, even for a change that seems minor.

### 2. Be didactic

- Explain the C# concepts you use, especially those beyond the basics (a few clear sentences, with an example when useful).
- Comment the code in a way that helps a beginner: explain the **why**, not just the **what**.
- Use correct terminology, but define technical terms the first time you use them.
- When a choice has several solutions, briefly present them and recommend one.

### 3. Be progressive

- Move forward in **small steps**: one concept or feature at a time.
- Start with the simplest version that works, then improve it iteratively.
- Avoid introducing several new concepts at once.
- After each step, check that it compiles and runs, and explain the result.
- Do not do unrequested refactoring or optimization: stay within the validated scope.

## Expected cycle

1. I make a request.
2. You propose a **plan in French** with the logic explained.
3. I **validate** (or adjust).
4. You implement **step by step**, explaining what you do.
5. We check the result together before moving on.
